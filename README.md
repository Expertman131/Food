# васаби. — кликабельный прототип MVP

Прототип собственного приложения доставки: клиентская часть (мобильное приложение) и веб-админка ресторана.
Сделан по 10 скриншотам существующего приложения на Foodpicasso и по ТЗ «Мобильное приложение доставки еды для собственного ресторана».

**Инструкция для владельца ресторана** — без технического жаргона: как открыть, два режима, семь разделов админки, типовые задачи по шагам, свои фото, честные ограничения и частые вопросы. Файл `guide.html`, на публикации открывается по адресу `https://expertman131.github.io/Food/guide.html`. В самом демо ссылка есть в правой панели — блок «Инструкция».

## Как открыть

Двойной клик по `index.html` — всё работает локально, без сервера и сборки.
Если прототип выложен на GitHub Pages, адрес вида `https://<логин>.github.io/<репозиторий>/` — он открывается в любом браузере, в том числе с телефона.

Справа от телефона — список всех экранов: клик по названию сразу переходит на нужный экран.
Кнопка «Клиент / Админ-панель» сверху переключает режим.

```
index.html      разметка оболочки
guide.html      инструкция для владельца (без жаргона, с группировкой по задачам)
PLAN.md         план перехода от прототипа к боевому приложению: этапы, бюджет, развилки
styles.css      тема и компоненты
data.js         меню, промокоды, правила доставки и лояльности
qr.js           генератор QR-кодов (своя реализация, без внешних библиотек)
geo.js          карта, геокодинг и проверка зоны доставки
app.js          состояние, роутер, клиентские экраны
admin.js        админ-панель
assets/         фото блюд
assets/vendor/  Leaflet 1.9.4 (BSD 2-Clause, лицензия рядом с библиотекой)
```

Карта и геокодинг работают через бесплатные сервисы без ключей и оплаты: тайлы OpenStreetMap, поиск адреса — Photon. Библиотека Leaflet лежит в проекте, поэтому интернет нужен только для самих тайлов и поиска адреса.

## Что кликается и работает

**Клиент (14 экранов)**

| Экран | Что работает |
|---|---|
| Главная | поиск сразу сверху, hero-баннер с сетом, карусель акций (свайп, стрелки, snap и точки), карточка «Повторить заказ» в один тап, лента любимого (4 блюда), строка «Категории» как быстрые переходы и ссылка «Все 10 блюд» |
| Каталог меню | сюда ведут чипсы категорий и поиск на главной и ссылка «Все 10 блюд»: поиск, фильтр по 7 категориям с «Все» во главе, сетка блюд, сердечко избранного, блюда в стоп-листе помечены «Нет в наличии» |
| Карточка блюда | фото, честный состав и аллергены по блюду, модификаторы с доплатой, степпер, избранное, добавление в корзину |
| Корзина | позиции, степперы, пересчёт, допродажи к заказу, «Добавьте всё», минимальный заказ, итог |
| Оформление | доставка / самовывоз / к столу, контакты, адресная книга, **карта с зоной доставки и проверкой адреса**, комментарий, слоты времени, способы оплаты, валидация полей |
| Оплата | сводка, время доставки, промокод, списание доступных бонусов одной кнопкой, оплата с анимацией → статус заказа |
| Статус заказа | таймлайн из 5 шагов, автопереход каждые 6 секунд, карточка курьера, отмена заказа клиентом |
| Отказ / отмена | отдельный экран: причина, что с деньгами, сумма возврата, повтор заказа в один тап |
| Мои заказы | история, повтор заказа в один клик, время доставки в заказе, обновление истории |
| Избранное | сердечко в шапке со счётчиком, список любимых, «Добавить всё в корзину» |
| Профиль | карточка гостя, демо-баланс и история бонусов со сроком сгорания каждого начисления, **кэшбэк по каналам и правила трат**, контакты, адресная книга, избранное, вход сотрудника |
| Акции | карточки акций из `BANNERS`, применение промокода в один тап, скрытые в админке акции здесь же не показываются |
| О ресторане | точки из общего справочника, часы, контакты, QR-меню |
| QR-меню стола | открывается по ссылке с листа на столе: карточка стола, категория, блюда, заказ «к столу» без регистрации и оплаты онлайн |
| Вход по SMS | телефон → код → вход, согласие 152-ФЗ |

**Админ-панель (7 разделов)**

- **Заказы** — лента в реальном времени, вкладки «Новые / В работе / Завершённые», смена статуса, печать на кухню, отклонение с выбором причины (гость видит её в приложении), создание тестового заказа (он появляется в приложении гостя). **Фильтры:** поиск по номеру заказа, имени, телефону и адресу; сортировка по времени и сумме; панель фильтров — дата заказа, статус, способ получения (доставка / самовывоз / к столу), способ оплаты, точка, сумма от и до, причина отмены; выгрузка отфильтрованных заказов в CSV.
- **Меню** — блюда, цены, стоп-лист (настоящий: блюдо сразу пропадает из меню гостя), отметка «на главной» (максимум 6), **создание и правка блюда**: название, категория, обычная цена, скидка 0–90%, вес, метка («Хит», «Выбор шефа» или свой текст), своё фото, описание, состав и аллергены. Демо-фото доступны как необязательные визуальные миниатюры. Новое блюдо сразу попадает в каталог, поиск и QR-меню. Есть **импорт меню из CSV** с шаблоном, предпросмотром и обновлением дублей. **Фильтры:** поиск по названию, метке и категории; сортировка по имени, категории и цене; панель фильтров — категория, состояние (в меню или стоп-лист), отметка «На главной».
- **QR-меню** — листовка на каждый стол: адрес ссылки подставляется автоматически из того, где открыт прототип, QR считается на лету, можно скачать PNG и распечатать листы A4 по 4 стола, открыть меню конкретного стола как гость.
- **Маркетинг** — **бонусная система**: включение, **кэшбэк по каналам** (доставка и самовывоз — два отдельных процента), **правила трат** (порог суммы и надбавка в процентных пунктах, пороги добавляются и убираются), максимальная доля оплаты баллами и **срок списания начисленных баллов в месяцах** (0 — не сгорают), живой пример расчёта; промокоды на всю корзину (процент, фиксированная сумма или бесплатная доставка, минимальная сумма заказа, включение/выключение), карусель акций: порядок ↑↓, **создание и редактирование существующих баннеров**, связь с промокодом / блюдом / экраном, своя картинка JPG или PNG. Метка вроде «−15%» — только текст на баннере; скидку считает выбранный промокод. Демо-фоны выбираются миниатюрами, без технических имён файлов. Push-кампания настраивается по аудитории, тексту, промокоду и времени, но сохраняется только в демо-журнал. **Фильтры:** промокоды — поиск по коду, состояние (включён/выключен), тип скидки, сортировка по коду, числу использований и минимальной сумме; журнал рассылок — фильтр по аудитории.
- **Клиенты** — база автоматически пополняется из заказов с телефоном, из импорта CRM и содержит шесть исходных демо-гостей; у каждой карточки виден источник. Есть сегменты, **ручное начисление баллов без модального окна** (форма раскрывается прямо под гостем: быстрые суммы +100/+500/+1000 или своя), удаление с подтверждением и **импорт из старой CRM** (файл CSV или вставленный текст: `Имя;Телефон;Заказы;Сумма;Бонусы;Сегмент`, разделитель «;» или «,», первая строка может быть заголовком; сначала показывается предпросмотр — кого добавим, у кого обновим историю, какие строки не разобрались; телефон сверяется по цифрам, гость с тем же номером второй раз не заводится). **Фильтры:** поиск по имени и телефону (по цифрам, без кода страны и пробелов), сортировка по имени, числу заказов, сумме, баллам и дате последнего заказа, панель фильтров — сегмент и источник.
- **Аналитика** — считается по истории заказов, а не по зашитым константам: **период** (7 дней / 14 дней / 30 дней / вся история), выручка, количество заказов, средний чек, доля доставки, самовывоза и заказа к столу, график по дням недели, топ блюд, отчёт по четырём неделям. Отменённые и отклонённые заказы в выручку не входят и показываются отдельной строкой. **Настоящая выгрузка:** «Выгрузить CSV» (разделитель «;», BOM — открывается в Excel) и «Выгрузить Excel» (настоящий .xlsx: ZIP с SpreadsheetML собирается в браузере). Обе кнопки отдают файл с теми же цифрами, что на экране, и пометкой «демо-данные» внутри.
- **Настройки** — цена доставки, порог бесплатной доставки, минимальный заказ, время приготовления; **добавление и редактирование точек** (название, адрес, часы, доставка или только самовывоз, **радиус зоны доставки в километрах** — координаты новой точки определяются по адресу автоматически); **сотрудники и роли** (добавление по имени и телефону, смена роли). Точка сразу появляется в самовывозе, на экране «О ресторане» и в QR-меню.

Общее состояние: корзина клиента, стоп-лист, скидки, акции, точки, сотрудники, база гостей, бонусные балансы и статусы заказов общие для обеих частей — изменения в админке видны гостю сразу. Импортированные блюда и гости, новые заказы и демо-журнал рассылок живут в том же состоянии текущей вкладки.

## Механики, добавленные после разбора конкурентов

- **Заказ по расписанию.** На оформлении — переключатель «Как можно скорее / К определённому времени» и слоты с шагом 30 минут на сегодня и завтра. Слоты считаются от часов работы выбранной точки и от текущего времени + 60 минут на приготовление (30 минут для самовывоза). Выбранное время сохраняется в заказе, видно в оплате, в истории и в админке.
- **Адресная книга.** Два сохранённых адреса («Дом», «Офис») плюс добавление своего: выбор подставляет адрес в поле доставки, удаление убирает адрес. Книга доступна и в оформлении, и в профиле.
- **Простые бонусы вместо пустой витрины iiko.** В «Маркетинге» включается программа и задаются кэшбэк для доставки и для самовывоза, правила трат (порог суммы и надбавка), максимальная оплата баллами и срок списания начисленных баллов в месяцах (0 — не сгорают). Один балл равен одному рублю, уровней нет. Профиль, оплата и база гостей читают один баланс по телефону. Гость одной кнопкой списывает доступный максимум; кэшбэк считается от блюд после промокода без доставки и начисляется один раз при статусе «Доставлено». Отмена или отказ возвращает списанные баллы. Ручное начисление в «Клиентах» попадает в историю. Бонусы хранятся лотами с отдельным сроком: списание идёт первым по тому лоту, который сгорит раньше, а просроченный остаток списывается один раз и попадает в историю строкой «Срок списания истёк». Срок действует на новые начисления: уже начисленные баллы сохраняют свой срок, а срок настройки изменить их задним числом не может. Это локальный демо-кошелёк, а не интеграция с iiko: после перезагрузки возвращаются исходные балансы.
- **Стоп-лист.** Переключатель в админке «Меню» сразу убирает блюдо из меню гостя: карточка помечается «Нет в наличии», кнопка «+» исчезает, блюдо нельзя заказать. Возврат в меню — одной кнопкой.
- **Минимальный заказ.** Порог 300 ₽ виден в корзине («не хватает X ₽») и блокирует переход к оплате. Значение меняется в админке и сразу действует в приложении.
- **Честные аллергены.** У каждого блюда свой состав и свой список аллергенов — чизкейк содержит молоко и глютен, латте — молоко, сашими — рыбу. Раньше один и тот же текст показывался для всех блюд.
- **Экран отказа.** Отказ ресторана (с выбором причины в админке) и отмена клиентом ведут на отдельный экран: причина, что с деньгами, сумма возврата и повтор заказа в один тап. Раньше отклонённый заказ показывался гостю как «Заказ принят».
- **Избранное и повтор заказа.** Сердечко в карточке блюда и в шапке со счётчиком, отдельный экран избранного с кнопкой «Добавить всё в корзину», карточка «Повторить заказ» на главной.
- **Допродажи.** В корзине — блок «Добавьте к заказу» с блюдами, которые заказывают вместе с текущими, и кнопкой «Добавить всё».
- **Логотип → главная.** Клик по «васаби.» в шапке сбрасывает стек экранов и возвращает на главную; если гость пришёл со стола, заказ «к столу» снимается.
- **Номера заказов — короткие и подряд.** Вместо случайных «bb5cc2» заказ получает короткий номер вида «2401»: номера идут подряд, их удобно назвать вслух, и в приложении гостя и в админке они выглядят одинаково. Счётчик живёт в открытой вкладке — после перезагрузки номера начинаются заново; настоящие номера выдаёт касса.
- **Значок в пустой корзине был не виден.** Правило для иллюстрации пустого состояния цепляло и стрелку «Открыть меню»: она становилась лаймовой на лаймовой кнопке и пропадала. Теперь правило относится только к иллюстрации, а не ко всем значкам внутри блока. Проверено на всех 14 экранах гостя — значков, совпадающих по цвету с фоном, больше нет.
- **Акции на виду.** `BANNERS` в `data.js` — единственный источник акций: он питает карусель на главной, экран «Акции» и раздел «Маркетинг» в админке. Карусель листается свайпом, колёсиком и стрелками в заголовке, карточки прилипают к началу (scroll snap), следующая видна краем, точки снизу показывают позицию. Тап открывает то, что обещано в карточке: блюдо, промокод (сразу в корзине, с проверкой минимальной суммы) или экран. Предпоследняя плитка — «Все акции». В админке каждую акцию можно выключить и переставить стрелками ↑↓ — гость видит изменения сразу, потому что и лента, и экран акций читают один и тот же список. Выключенный промокод нельзя применить ни кнопкой, ни вводом вручную, а если его выключить у уже добавленного в заказ — скидка исчезает из расчёта.
- **Фильтр там, где он работает.** На главной нет чипса «Все» и вообще нет подсвеченного фильтра: там лежит лента любимого (4 блюда), а подсвеченное «Все» обещало бы 10 и выглядело сломанным. Строка «Категории» на главной — не фильтр, а быстрые переходы: обводка вместо заливки, стрелка у названия, тап открывает каталог сразу с этой категорией. В каталоге тот же ряд работает как настоящий фильтр — там и подсвеченная категория. Поиск на главной при вводе переносит в каталог с результатом и по пути сбрасывает выбранную категорию — поиск ищется по всему меню, иначе leftover-категория прятала бы половину блюд без единого следа в интерфейсе.
- **Найти своё блюдо — с первого экрана.** Поиск на главной поднят под шапку: раньше он стоял под акциями, на 1094 px от верха, и до него нужно было прокручивать полэкрана. Теперь он виден сразу, а hero-баннер целиком остаётся на первом экране.
- **Горизонтальные ленты видно, что они листаются.** У лент категорий полосы прокрутки нет, поэтому у правого края добавлено затемнение (`.chips-wrap::after`): на 360 px видно 3 категории из 7, и без этого знака гостю не сообщали, что справа есть ещё.
- **Главная: «Попробуйте любимое» ведётся из админки.** В разделе «Меню» у каждого блюда есть звезда «На главной» и отдельная панель со списком отмеченных. Метка меняет ленту на главной гостя сразу (общее состояние), лимит — 6 блюд (`RULES.featuredMax`), седьмое не добавляется: главная не должна превращаться в каталог. Блюдо из стоп-листа в ленту не попадает, и в панели это подписано. Если отметок нет — блок на главной не показывается вовсе, пустой заголовок с нулём блюд гость не видит.
- **Поля экрана.** Отступ по краям экрана — 16 px (`--pad`), он задаёт только `.section`; у `.dish-grid`, `.chips`, `.search` своих полей нет, иначе они складывались бы вдвое. Карточка блюда на экране 393 px — 175 px вместо 158 px, на 360 px — 158 px.
- **Добавление блюда — на первом экране раздела.** Форма стояла под таблицей всех блюд, то есть на третьем экране вниз: на телефоне до «Новое блюдо» надо было долистать мимо десяти позиций. Теперь форма первая в разделе «Меню», над таблицей, а в шапке таблицы есть кнопка «+ Добавить блюдо» — она возвращает к форме и ставит курсор в поле названия. Кнопка «Создать блюдо» липнет к низу окна, пока поля заполняются. Правка блюда (иконка-карандаш в строке таблицы) открывает ту же форму с уже подставленными данными.
- **Своё фото блюда — основной сценарий.** Поле «Своё фото блюда» принимает снимок с телефона, обрезает его по квадрату, ужимает до 900 px и показывает предпросмотр. Технического списка JPG больше нет: семь демо-фото спрятаны в необязательный раскрывающийся блок и выбираются по миниатюрам. Они нужны только как временная картинка, если своего снимка пока нет. Кнопка «Вернуть прежнее фото» отменяет последнюю замену. Ограничение прототипа: загруженное фото живёт только в открытой вкладке — после перезагрузки возвращаются демо-данные.
- **Метка и скидка — разные настройки.** Под полем метки стоят кнопки готовых вариантов; свою метку до 24 символов можно просто вписать в поле, без системного выпадающего списка. Метка ничего не меняет в цене. Скидка 0–90% задаётся рядом с обычной ценой: гость видит новую цену и старую зачёркнутой в каталоге, карточке, избранном и корзине. Доплаты за модификаторы не уменьшаются. Промокод применяется дополнительно к сумме корзины после скидок на блюда — это осознанное демо-правило, перед боевым запуском владельцу нужно подтвердить, что скидки должны суммироваться.
- **Свой баннер с понятными размерами.** В «Маркетинге» можно изменить уже существующую акцию, включая «−15%»: метка редактируется отдельно, а при выборе промокода подставляется автоматически. Поле «Свой баннер» принимает JPG/PNG, ужимает файл до 1600 px по ширине и показывает предпросмотр. Рекомендуемый исходник — **1600 × 800 px, горизонтальный 2:1**; важные текст и блюдо держать по центру, потому что карусель на главной обрезает верх и низ чуть сильнее, чем полный экран акции. Демо-фон можно выбрать по миниатюре в отдельном необязательном блоке, но основной путь — загрузить собственный баннер.
- **Точки и сотрудники добавляются в «Настройках».** У точки редактируются название, адрес, часы и тип работы; она сразу попадает в самовывоз, «О ресторане» и QR-листы. Сотруднику задаются имя, телефон и роль. Вход в демо-панель: «Профиль» → «Доступ сотрудника» → выбрать человека → «Открыть демо-панель»; выбранные имя и роль видны в шапке админки. Это не регистрация: SMS, пароли, приглашения и настоящее ограничение кнопок по роли требуют серверной авторизации.
- **Таблица меню читается, а не сжимается.** Колонка «Вес» была 43 px, и «32 шт. · 920 г» переносилось по одному слову в строке — строка вырастала до 121 px. Теперь у таблицы есть минимальная ширина, она прокручивается внутри своей панели (страница целиком не едет вбок), короткие колонки не переносятся, а кнопки действий стоят в одну строку: высота строки — 70 px. Широкие таблицы заменяются карточками уже на 1140 px, а не на 560 px: раньше на ноутбуке с узким окном колонка действий («Стоп-лист», правка, звезда) уезжала за горизонтальную прокрутку, и блюдо нельзя было ни отредактировать, ни снять с продажи, не прокручивая таблицу вбок. Теперь на 1140 → 390 px те же действия видны в карточке блюда. Проверено измерениями: на всех проверенных ширинах горизонтальной прокрутки у панели нет. Позже и этот список перешёл на общий паттерн «строка + Детали» вместе с остальными разделами админки.
- **Форма блюда разложена по правилам сетки.** Поля стояли без единого ритма: часть с видимыми подписями, часть по placeholder, ряды разной высоты (86 px против 66 px), поля в строке не совпадали по высоте. Теперь у каждого поля своя подпись над ним, все поля одинаковой высоты 44 px, сетка — две равные колонки, а «Название блюда» занимает всю ширину: на телефоне сетка становится одной колонкой. Измерено на 1400 / 900 / 560 / 390 px — подписи совпадают по базовой линии, поля равны.
- **Предпросмотр push не липнет к кнопке.** Строка с получателями («Сергей, Анна, Дмитрий и ещё 3») стояла вплотную к кнопке «Смоделировать отправку»: зазор был 0. Теперь между предпросмотром и получателями 14 px, между получателями и кнопкой 12 px.
- **Инспектор рассказывает, что уже работает.** Список «Что работает» справа от рамки разделён на «Приложение гостя» и «Админ-панель» и перечисляет то, что действительно есть в прототипе: от поиска на главной до импорта меню и гостей и настройки демо-рассылки. Раньше список остался от первой версии и половины уже не было в проекте. На широком экране панель листается сама: она липкая, а список стал длиннее окна — раньше её низ был просто недоступен.
- **Карточка блюда открывается всегда.** В списке экранов справа есть пункт «Карточка блюда» — раньше он открывал пустой экран («Блюдо не найдено»), потому что блюдо в нём выбрать нельзя. Теперь в этом случае показывается первое доступное блюдо, а последнее открытое — при повторном заходе. Если блюдо всё же недоступно, вместо пустоты даётся кнопка «Открыть меню».
- **Модификатор не переезжает на другое блюдо.** Идентификаторы модификаторов («острое», «авокадо», «фирменный соус») общие для всех блюд, поэтому при переходе на другое блюдо выбор сбрасывается. Раньше отмеченная доплата молча уезжала в следующую карточку и попадала в заказ.
- **Админка ведёт всё, что не приходит из iiko.** Пока касса не подключена, меню, акции и база гостей живут в панели: можно завести блюдо (оно сразу в каталоге, поиске и QR-меню), создать акцию на главной, начислить гостю баллы, удалить гостя и **залить гостей из старой CRM** — это подготовка к переезду с Foodpicasso. Перед импортом файл показывается списком: кого добавим, у кого обновим историю заказов, какие строки не разобрались. Сверка по телефону, а не по строке: «+7 916 330-12-04» и «8 916 330 12 04» — один и тот же гость.
- **Импорт меню — через CSV с предпросмотром.** В разделе «Меню» можно скачать шаблон, заполнить его в Excel и сохранить как CSV UTF-8 с разделителем «;» либо вставить строки текстом. Колонки: `Название;Категория;Цена;Скидка %;Вес;Метка;Описание;Состав;Аллергены;На главной`. До применения видно новые блюда, дубли и ошибки. Дубль определяется по названию без учёта регистра и лишних пробелов: существующее блюдо обновляется, его фото, модификаторы, стоп-лист и идентификатор сохраняются. Строки с ошибками пропускаются, остальные можно применить. Лимит «на главной» — шесть блюд — учитывается заранее. Фото и модификаторы файлом не переносятся; новым блюдам ставится демо-фото их категории. Прямой синхронизации с Foodpicasso или iiko нет.
- **Гости попадают в базу из заказов.** После оформления доставки или самовывоза телефон сверяется по цифрам: существующая карточка обновляется, новая создаётся с нулём бонусов и источником «Заказ». Тестовый заказ из админки работает так же. Импортированные из CRM записи получают источник «CRM», шесть исходных карточек — «Демо». Анонимный заказ со стола гостя не создаёт. Число заказов и сумма увеличиваются при оформлении и пока не пересчитываются при последующей отмене или отказе; имя существующего гостя заменяется именем из последнего заказа.
- **Push настраивается, но не отправляется.** Можно выбрать всю базу, сегмент или источник гостей, ввести заголовок и текст, добавить действие с активным промокодом, выбрать «сейчас» или будущие дату и время. Предпросмотр показывает уведомление, число и имена получателей из текущей базы. Сохранение добавляет кампанию в журнал со статусом «Не отправлено»: ни реальной доставки, ни фонового запуска по расписанию в статическом прототипе нет.
- **QR-меню на столе.** Админ-панель → «QR-меню»: выбираешь точку и номера столов, получаешь ссылки вида `…index.html#menu?table=12&loc=l1`, PNG для печати и листы A4 по 4 стола. Гость сканирует код камерой, попадает на экран меню стола без регистрации, выбирает блюда и отправляет заказ «к столу» — у него свой короткий статус-флоу («Принят → Готовим → Собран → Подан к столу»), оплата у стола, время приготовления — из настроек. Стоп-лист админки действует и там. QR считается своим кодером (`qr.js`): байтовый режим, уровни L/M, версии 1–10, маски по штрафам — проверен на 34 реальных ссылках, совпадает бит в бит с библиотекой `qrcode` и читается декодером без единой синдроменной ошибки.
- **Фильтры в админке — один шаблон, а не свалка селектов.** В чужих админках (Foodpicasso) фильтров больше, но часть относится к сети ресторанов: ERP, зоны доставки, рекламные кампании, уровни лояльности, согласия, пол и день рождения гостя. У «васаби.» таких данных нет, и фильтр по несуществующему полю — мёртвый контрол. Правило: фильтр ставится только там, где он реально сужает список. Один шаблон на все разделы: **поиск всегда на виду слева, сортировка всегда на виду справа, остальное — в панели «Фильтры»**; выбранное показывается чипами с крестиком и кнопкой «Сбросить фильтры». Внутри одной группы варианты соединяются через «или», между группами — через «и». Счётчик у варианта честный и фасетный: он считает элементы по списку, отфильтрованному всеми фильтрами, кроме этой группы, — поэтому «Самовывоз · 0» означает «таких заказов нет», а не ошибку. Счётчик вкладок заказов считается по всем фильтрам, кроме группы «Статус», иначе вкладка «В работе» показывала бы ноль. Группа, у которой нет ни одного варианта, не рисуется. Перерисовка не сбрасывает ввод: при поиске и при переключении чипа меняются только список, чипы и счётчики — поле поиска не пересоздаётся, каретка остаётся на месте; после снятия фильтра фокус переходит на кнопку «Фильтры». Разделы: «Заказы» (поиск, сортировка, дата, статус, способ получения, оплата, точка, сумма от и до, причина отмены, выгрузка CSV из отфильтрованного списка), «Клиенты» (поиск по имени и телефону, сегмент, источник, сортировка по имени / числу заказов / сумме / баллам / последнему заказу), «Меню» (категория, состояние «в меню или стоп-лист», отметка «На главной»), «Промокоды» (код, включён/выключен, тип скидки), «Журнал рассылок» (аудитория).
- **Аналитика перестала врать.** Раньше цифры отчёта были зашиты в коде константами и не менялись: фильтр по периоду был бы враньём, поэтому его и не было. Теперь в прототип посеяна правдоподобная история заказов за последние четыре недели (демо-гости заказывают по своему плану: сколько заказов, с каким интервалом), и весь отчёт считается по ней — выручка, средний чек, доля доставки, график по дням недели, топ блюд, разбивка по неделям. Сверху появился выбор периода (7 / 14 / 30 дней / вся история), рядом показывается, сколько заказов попало в него. Отменённые и отклонённые заказы в выручку не входят — они считаются отдельно и видны отдельной строкой, потому что деньги за них не пришли. Сравнение с прошлым периодом честно пишет «до этого периода заказов ещё не было», если сравнивать не с чем, — вместо пустой строки или выдуманного процента.
- **Выгрузка отчёта — настоящий файл.** Кнопки «Выгрузить CSV» и «Выгрузить Excel» в аналитике были заглушкой: они показывали тост и ничего не отдавали. Теперь браузер собирает файл и отдаёт его на диск. CSV — с разделителем «;» и BOM, чтобы Excel открыл его без плямб. Excel — настоящий .xlsx: ZIP-архив со SpreadsheetML собирается прямо в браузере (свой CRC32 и запись центрального каталога), файл открывается в Excel, Numbers и LibreOffice. Внутри — те же цифры, что на экране за выбранный период, и честная пометка «демо-данные» в первой строке.
- **Карта и зона доставки — бесплатная, без ключей и без денег.** На оформлении доставки появилась карта (Leaflet 1.9.4 лежит в проекте, тайлы — OpenStreetMap, подпись «© OpenStreetMap» на месте). Адрес ищется через Photon (без ключа и оплаты); квартира, подъезд и этаж из запроса выбрасываются, сокращения улиц разворачиваются в слова. Круг вокруг точки ресторана — это зона доставки: радиус в километрах задаётся владельцем в «Настройках» и рисуется на карте. Гость вводит адрес и жмёт «Найти на карте»: если адрес внутри круга — приложение называет точку, которая привезёт («Доставим из «Васаби на Ташкентской» — 2,0 км от ресторана»), если вне — прямо говорит, что доставки по этому адресу нет, показывает ближайшую точку и расстояние до неё и предлагает самовывоз одной кнопкой. Молча пропустить заказ в другой город нельзя — это дыра в доставке. Если адрес не нашёлся автоматически, гость ставит точку кликом по карте. Новой точке, добавленной в админке, координаты ставятся по её адресу автоматически: без них зона не работает, и админка так и пишет. Чего карта не умеет: подъезд, этаж, двор и вход в ТЦ, авто-парковку, подъездные пути и «дойти 200 метров» — это зона полигона, а у нас круг. Яндекс и 2ГИС не подключены, платного геокодера нет, адреса из 1С не подтягиваются. Без интернета экран остаётся рабочим: карта пустая, адрес вводится текстом.
- **Кэшбэк по каналам и правила трат.** В «Маркетинге» программа лояльности настраивается отдельно для доставки и для самовывоза (7% и 3% по умолчанию) — это разные каналы с разной маржой. Сверху настраиваются **правила трат**: порог суммы и надбавка в процентных пунктах («от 1 000 ₽ — +1 п.п.», «от 2 000 ₽ — +2 п.п.»); срабатывает наибольший подходящий порог, поэтому доставка на 2 000 ₽ идёт уже по 9%. Пороги добавляются и убираются прямо в панели, гость сразу видит новый процент в оплате и в профиле. Заказ к столу по QR-коду идёт без аккаунта гостя — по нему баллы не начисляются, и в панели для него нет отдельной настройки, потому что она не смогла бы примениться. Начисление — после выполнения заказа, а не в момент оплаты; отмена возвращает списанные баллы.
- **Один список вместо «таблица + карточки».** В пяти разделах админки (Клиенты, Промокоды, QR-меню, Отчёт, оба предпросмотра импорта) список рисовался дважды: широкой таблицей для десктопа и набором карточек для узкого экрана, а CSS выбирал, какой из них виден. Отсюда две беды: в разметке лежали два одинаковых набора данных (любая новая функция в этих разделах обязана была помнить про оба), а на телефоне карточки теряли часть колонок. Теперь у всех списков одна конструкция — строка с кнопкой «Детали», которая раскрывает подробности под строкой. Таблицы и карточки из кода и из CSS убраны, поведение на всех ширинах одинаковое, а дублирующиеся `id` и второй источник цифр исчезли. Заодно уехали мёртвые правила: `.a-table*`, `.a-cards` и контейнерное правило на 1140 px, которые больше ничего не описывали.

## Что намеренно не подключено

- **База данных и файловое хранилище.** Все правки меню, акций, точек и сотрудников, импортированные строки, база гостей, бонусные балансы и история, журнал рассылок, а также загруженные фото и баннеры живут только в текущей открытой вкладке. Перезагрузка возвращает демо-данные; для сохранения и совместной работы нужны сервер и база данных.
- **Авторизация и права сотрудников.** Выбор человека в «Профиле» — демонстрация интерфейса, а не вход. SMS, пароли, приглашения, сеансы и ограничение действий по роли не реализованы.
- **iiko и Foodpicasso.** Заказы не уходят в iikoDelivery, чек не печатается в iikoKitchen. Бонусы работают только как отдельный демо-счёт внутри прототипа и не синхронизируются с iiko. Прямого импорта по API из Foodpicasso или iiko нет — только CSV-файлы с предпросмотром. Для интеграции с iiko требуются лицензии iikoDelivery + iikoKitchen и API-ключи тестового стенда.
- **Оплата.** Кнопка оплаты имитирует успешный ответ; чека по 54-ФЗ нет — нужен реальный эквайринг (ЮKassa/СБП).
- **Push и SMS.** Push-кампания сохраняется только в локальный демо-журнал: сообщения не отправляются, отложенные кампании сами не запускаются. SMS-код тоже не отправляется, а статус заказа меняется автоматически по таймеру.
- **Геокодинг и карта.** Карта бесплатная (Leaflet + OpenStreetMap), адрес ищется Photon без ключа. Не подключены Яндекс и 2ГИС, платный геокодер, адреса из 1С и разбор подъездов, дворов и входов в ТЦ: зона доставки у нас круг вокруг точки, а не полигон по улицам. Без интернета карта остаётся пустой, адрес вводится текстом.
- **Слоты времени.** Считаются по часам работы точки в справочнике, без загрузки реального графика загрузки кухни и без подтверждения оператором.
- **Фильтры по данным, которых у нас нет.** Фильтр по ERP и кассе (нет связи с iiko), по рекламным кампаниям (кампаний нет), по уровням лояльности (у нас кэшбэк с порогами по сумме, без уровней), по согласиям на рассылку (не храним), по полу, дню рождения и дате регистрации гостя (такие данные не собираем). Зоны доставки в прототипе есть (круг вокруг точки), но фильтра по зоне нет: заказы в нём не размечаются, фильтровать нечего. Отдельного фильтра «источник» в заказах нет: источник виден по способу получения — приложение или QR-код, второй фильтр по тому же только путает.
- **Комбо-акции «2+1», «3+1», «1+1 = 3».** В чужой админке это отдельный тип акции. У нас таких механик нет, и это не фильтр, а правило расчёта в корзине — его нужно придумать и описать гостю.

## Дизайн

Тёмная тема «васаби.» снята со скриншотов: фон #080B08, карточки #151B14, лаймовый акцент #C6F16E, панели #1C2716, шрифт Inter / SF Pro.
Второй бренд из скриншотов («КАЙ», светлая веб-версия) в этот прототип не вошёл — добавляется отдельной темой, если нужно.

**Шрифтовая шкала и сетка отступов.** Раньше размеры шрифта и отступов были заданы по месту: 24 разных кегля и 28 разных значений отступов. Теперь у каждого — токен в `:root` файла `styles.css`:

- `--fs-11 … --fs-40` — 11 ступеней: от мелочи в 11,5 px (старая цена, счётчики) до 40 px (баланс бонусов). Названия — по шагу, не по пикселям.
- `--sp-2 … --sp-60` — 18 чётных шагов: 2 px — самый мелкий зазор, дальше шаг 2, 4, 6 и так до 60 px. Все значения кратны двум, поэтому блоки встают на одну сетку.

В `styles.css`, `app.js`, `admin.js` и `guide.html` заменены все «сырые» пиксели в `font-size`, `margin`, `padding` и `gap` на эти токены. Вёрстка не поехала: старое и новое значения сверены скриптом по каждой замене — расхождений больше 2 px нет, кроме двух намеренных округлений: `padding-top:44px → 48px` (верхний отступ на экране входа) и нижний отступ инструкции `80px → 60px` — там это просто воздух внизу страницы. Исключение одно: у `.sr-only` остались `margin:-1px` и `width:1px` — это маскировка, а не отступ, и токеном её не заменить.

## Экран телефона

Телефон в прототипе — нарисованная рамка на CSS (`.device`), а не эмулятор устройства и не расширение браузера: сборки нет, прототип открывается двойным кликом по `index.html`.

Размер выбирается в верхней панели — список «Размер экрана». Пресеты сняты с реальных разрешений массовых телефонов, а не округлены «под 390»: вёрстка проверяется ровно на том экране, что у гостя в руке.

| Пресет | Экран | CSS-размер | Кого представляет |
|---|---|---|---|
| iPhone 15/16 | 393 × 852 | по умолчанию | самый распространённый айфон |
| iPhone Pro Max | 430 × 932 | крупный экран | «плюс»-модели, планшетофоны |
| Pixel 8/9 | 412 × 892 | средний Android | Pixel, Xiaomi, Honor |
| Galaxy S24 | 360 × 780 | узкий Android | самый популярный Android-размер |
| iPhone SE | 375 × 667 | маленький экран | старые и бюджетные телефоны |
| Планшет | 768 × 1024 | iPad | показ гостю на планшете в зале |
| Терминал в зале | 1024 × 768 | горизонтальный | монитор кассы и киоск |
| Во весь экран | по окну | — | максимум места на мониторе |
| Свой размер… | любые числа | — | два поля «ширина × высота», применяются сразу |

Чем шире рамка, тем больше контента видно без прокрутки: сетка блюд переходит с 2 колонок на 3–4, слоты времени — с 4 на 6, инспектор переезжает под экран, а чёлка телефона исчезает.

**Рамка никогда не уменьшается ниже 90%.** Раньше она целиком вписывалась в окно и на ноутбуке сжималась до 71% — текст становился нечитаемым, кнопки мелкими для пальца. Теперь, если рамка не влезает по высоте даже в 90%, она остаётся в 90%, а нижняя часть долистывается страницей: пропорции телефона не искажаются, размер текста остаётся читабельным. О нехватке места честно сказано в инспекторе: «393 × 852 · 90% окна · низ экрана ниже, листать». Если окно уже самой рамки — она уменьшается по ширине (иначе уехала бы за экран).

**На настоящем телефоне** (ширина экрана до 560 px) муляж корпуса, статус-бар с 9:41 и масштабирование отключаются: приложение занимает весь экран ровно так, как оно выглядит у гостя, — в него можно тыкать пальцем без потерь. Инспектор и переключатель режимов остаются под ним.

Высота шапки сверху («васаби.», выбор размера, переключатель режима) измеряется в браузере и учитывается в двух местах: телефон прилипает под неё, а не за неё, и вписывается в оставшееся место. На узком окне шапка переносится в две строки — отступы пересчитываются сами.

Дополнительно:

- **Узкое окно** (до 960 px): инспектор уезжает под телефон. Там же рамка телефона перестаёт прилипать к шапке: в одной колонке прилипания она легла бы на список экранов.
- **Мобильный браузер** (до 640 px): подпись под названием в шапке скрывается, чтобы панель осталась в одну строку.

## Админ-панель на телефоне

Админка перестраивается по ширине собственного контейнера (`.admin-stage`), а не окна браузера: тот же расклад получает и телефон, и узкое окно десктопа, и колонка в половину монитора.

| Ширина панели | Что меняется |
|---|---|
| до 1140 px | устаревший порог: широкие таблицы админки больше не строятся вовсе — все списки (клиенты, промокоды, столы QR, отчёт, предпросмотры импорта гостей и меню) перешли на единый паттерн «строка + Детали», который одинаково читается на любой ширине. Карточки заказов сами выбирают число колонок (`auto-fit`, не уже 420 px) |
| до 1100 px | блоки «два в ряд» и статистика перестроются в 2 колонки |
| до 900 px | боковое меню уходит над контентом и становится чипами в строку, отступы уменьшаются |
| до 860 px | блоки «два в ряд» в одну колонку |
| до 760 px | содержимое шире панели получает свою горизонтальную прокрутку — страница целиком не уезжает |
| до 560 px | вкладки статусов переносятся, кнопки вырастают до ~45 px под палец, длинный адрес меню переносится, а не режется многоточием |
| до 420 px | статистика и сетки в одну колонку, адрес `admin.vasabi.ru` в шапке окна скрывается |

Ни один раздел не прячется за прокрутку: семь пунктов меню видны все (перенос в три строки), как и все вкладки статусов. Проверено скриптом на 360, 390, 480, 640, 768, 900, 1100 и 1440 px по всем семи разделам — ни обрезанного контента, ни общей горизонтальной прокрутки.

Список блюд — одна конструкция на все ширины, без замены на карточки: в строке фото, название, цена, статус, звезда «на главной», кнопка «Детали» и действия; категория, вес, скидка, состав, аллергены и доплаты раскрываются «Деталями» под строкой, узкая панель переносит блоки на вторую строку. Поиск и сортировка перерисовывают только список — фокус и мобильная клавиатура не слетают посреди набора. Проверено на 1400, 1140, 1000, 900, 760, 560 и 390 px: горизонтальной прокрутки нет ни на одной ширине, все кнопки строки доступны без неё.

Прокрутка вбок была: подписи для скринридера в шапках таблиц стояли по статическому месту, то есть за правым краем широкой таблицы, и на телефоне страницу можно было сдвинуть на 60–105 px. Теперь подписи прижаты к началу — проверено на всех семи разделах при ширине панели 390 и 430 px. Позже широкие таблицы админки ушли совсем: их место занял единый паттерн «строка + Детали», который не имеет колонок и потому не разъезжается на узком экране.

## Прокрутка

Перерисовка экрана не сбрасывает позицию: переключение шагатора, добавление в корзину, выбор категории и ввод в поиске сохраняют прокрутку. Кнопка «Назад» возвращает экран на ту же позицию, а переход на новый экран начинается сверху.

## Доступность и попадание пальцем

Проход по мобильным экранам с навыками `design-review` (accessibility + responsive). Мерялось скриптом в браузере: 14 экранов гостя на 360 / 375 / 393 / 430 px и все семь разделов админки.

- **Тап 44 px.** Чипсы категорий (41 px → 44 px), сегмент «Доставка / Самовывоз / К столу», кнопки «Назад», «+» в карточке, outline-кнопки и поля строк выросли до 44–48 px; в админке все кнопки и вкладки — 44 px. Мелкие иконки (сердечко избранного, стрелки карусели, удаление адреса) остались визуально 32–34 px, но получили невидимую площадку +6 px по краям — попадать надо по 44–46 px.
- **Главная кнопка не прячется.** «Оформить» и «Оплатить» прилипли к низу экрана (`.pdp-bar`, `position:sticky`): раньше на оформлении кнопка лежала на ~1400 px ниже сгиба, и её надо было искать прокруткой. Проверено на трёх позициях скролла — кнопка всегда у нижней границы.
- **Клавиатура.** Enter и Пробел срабатывают на самодельных кнопках (строки выбора адреса, способа оплаты, стола), после любой перерисовки фокус возвращается на тот же элемент, а после неудачной проверки встаёт на первое проблемное поле. Виден и лаймовый `:focus-visible`.
- **Скринридер.** У каждого экрана ровно один `h1` (в админке им стал заголовок раздела, подзаголовки панелей опустились до `h2`); самодельные контролы получили `role="button"`/`aria-pressed`, переключатели — `role="switch"`/`aria-checked`, активный пункт меню — `aria-current`, кнопка «Детали» — `aria-expanded`, панель фильтров — `aria-controls`, кнопки-иконки — имена, `role="application"` убран.
- **Страница не уезжает вбок.** Подписи, которые читает только скринридер (`.sr-only`), стояли по статическому месту — то есть в самом правом краю широкой таблицы админки, и растягивали страницу на 60–105 px: на телефоне её можно было случайно сдвинуть вбок. Теперь они прижаты к началу (`left:0`) и больше не тянут за собой страницу.
- **Ошибки полей.** `aria-invalid` + `aria-describedby` на само поле и `role="alert"` на текст ошибки: «Укажите адрес» теперь озвучивается и привязан к полю, а не просто нарисован красным.
- **Мобильный ввод.** У полей появились `autocomplete` (имя, телефон, адрес, `one-time-code` для кода SMS), `inputmode` для цифр, `enterkeyhint` («Далее» / «Готово» вместо «Enter» в середине формы) и `autocapitalize` — телефон не набирается в нижнем регистре, промокод сам становится ЗАГЛАВНЫМИ.
- **Мельчайший текст.** Нижняя граница — 11,5 px; остались 11 px только счётчики внутри пилюль 17–18 px (больше в них не влезает). Контраст проверен с учётом наложения полупрозрачных фонов — падений нет.

Аудит ручной (без axe-сканера): текст поверх фото и реальную озвучку скринридером скриптом не проверить — это смотрит человек.

## Публикация (GitHub Pages)

Прототип — обычные статичные файлы, сервер не нужен. `index.html` в корне репозитория, Pages раздаёт его по адресу `https://<логин>.github.io/<репозиторий>/` с HTTPS и без оплаты.

1. Завести репозиторий (имя, например `food-proto`) и включить в нём Pages: Settings → Pages → Source: Deploy from a branch → `main` / root.
2. Открыть ссылку с телефона — QR-коды из админки начнут вести на этот же адрес автоматически (`menuUrl()` берёт текущий домен), перегенерировать листы не нужно.
3. Ссылку можно укоротить редиректом, если для печати она слишком длинная.

Из России GitHub Pages открывается нестабильно: для показа гостям и печатных листов надёжнее любой российский статический хостинг с тем же `index.html` — код от этого не меняется.
