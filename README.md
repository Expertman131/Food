# васаби. — кликабельный прототип MVP

Прототип собственного приложения доставки: клиентская часть (мобильное приложение) и веб-админка ресторана.
Сделан по 10 скриншотам существующего приложения на Foodpicasso и по ТЗ «Мобильное приложение доставки еды для собственного ресторана».

## Как открыть

Двойной клик по `index.html` — всё работает локально, без сервера и сборки.
Если прототип выложен на GitHub Pages, адрес вида `https://<логин>.github.io/<репозиторий>/` — он открывается в любом браузере, в том числе с телефона.

Справа от телефона — список всех экранов: клик по названию сразу переходит на нужный экран.
Кнопка «Клиент / Админ-панель» сверху переключает режим.

```
index.html      разметка оболочки
styles.css      тема и компоненты
data.js         меню, промокоды, правила доставки и лояльности
qr.js           генератор QR-кодов (своя реализация, без внешних библиотек)
app.js          состояние, роутер, клиентские экраны
admin.js        админ-панель
assets/         фото блюд
```

## Что кликается и работает

**Клиент (14 экранов)**

| Экран | Что работает |
|---|---|
| Главная | поиск сразу сверху, hero-баннер с сетом, карусель акций (свайп, стрелки, snap и точки), карточка «Повторить заказ» в один тап, лента любимого (4 блюда), строка «Категории» как быстрые переходы и ссылка «Все 10 блюд» |
| Каталог меню | сюда ведут чипсы категорий и поиск на главной и ссылка «Все 10 блюд»: поиск, фильтр по 7 категориям с «Все» во главе, сетка блюд, сердечко избранного, блюда в стоп-листе помечены «Нет в наличии» |
| Карточка блюда | фото, честный состав и аллергены по блюду, модификаторы с доплатой, степпер, избранное, добавление в корзину |
| Корзина | позиции, степперы, пересчёт, допродажи к заказу, «Добавьте всё», минимальный заказ, итог |
| Оформление | доставка / самовывоз / к столу, контакты, адресная книга, комментарий, слоты времени, способы оплаты, валидация полей |
| Оплата | сводка, время доставки, промокод, бонусы, оплата с анимацией → статус заказа |
| Статус заказа | таймлайн из 5 шагов, автопереход каждые 6 секунд, карточка курьера, отмена заказа клиентом |
| Отказ / отмена | отдельный экран: причина, что с деньгами, сумма возврата, повтор заказа в один тап |
| Мои заказы | история, повтор заказа в один клик, время доставки в заказе, обновление истории |
| Избранное | сердечко в шапке со счётчиком, список любимых, «Добавить всё в корзину» |
| Профиль | карточка гостя, бонусы iiko (отключены), контакты, адресная книга, избранное, вход сотрудника |
| Акции | карточки акций из `BANNERS`, применение промокода в один тап, скрытые в админке акции здесь же не показываются |
| О ресторане | точки из общего справочника, часы, контакты, QR-меню |
| QR-меню стола | открывается по ссылке с листа на столе: карточка стола, категория, блюда, заказ «к столу» без регистрации и оплаты онлайн |
| Вход по SMS | телефон → код → вход, согласие 152-ФЗ |

**Админ-панель (7 разделов)**

- **Заказы** — лента в реальном времени, вкладки «Новые / В работе / Завершённые», смена статуса, печать на кухню, отклонение с выбором причины (гость видит её в приложении), создание тестового заказа (он появляется в приложении гостя).
- **Меню** — блюда, цены, стоп-лист (настоящий: блюдо сразу пропадает из меню гостя), отметка «на главной» (максимум 6), **создание и правка блюда**: название, категория, обычная цена, скидка 0–90%, вес, метка («Хит», «Выбор шефа» или свой текст), фото из набора или своё, описание, состав и аллергены. Новое блюдо сразу попадает в каталог, поиск и QR-меню.
- **QR-меню** — листовка на каждый стол: адрес ссылки подставляется автоматически из того, где открыт прототип, QR считается на лету, можно скачать PNG и распечатать листы A4 по 4 стола, открыть меню конкретного стола как гость.
- **Маркетинг** — промокоды на всю корзину (процент, фиксированная сумма или бесплатная доставка, минимальная сумма заказа, включение/выключение), карусель акций: порядок ↑↓, **создание и редактирование существующих баннеров**, связь с промокодом / блюдом / экраном, своя картинка JPG или PNG. Метка вроде «−15%» — только текст на баннере; скидку считает выбранный промокод. Push-рассылка — макет.
- **Клиенты** — база гостей, сегменты, ручное начисление баллов, удаление гостя с подтверждением, **импорт из старой CRM** (файл CSV или вставленный текст: `Имя;Телефон;Заказы;Сумма;Бонусы;Сегмент`, разделитель «;» или «,», первая строка может быть заголовком; сначала показывается предпросмотр — кого добавим, у кого обновим историю, какие строки не разобрались; телефон сверяется по цифрам, гость с тем же номером второй раз не заводится).
- **Аналитика** — выручка, заказы, средний чек, график по дням, топ блюд, выгрузка CSV/Excel.
- **Настройки** — цена доставки, порог бесплатной доставки, минимальный заказ, время приготовления; **добавление и редактирование точек** (название, адрес, часы, доставка или только самовывоз); **сотрудники и роли** (добавление по имени и телефону, смена роли). Точка сразу появляется в самовывозе, на экране «О ресторане» и в QR-меню.

Общее состояние: корзина клиента, стоп-лист, скидки, акции, точки, сотрудники и статусы заказов общие для обеих частей — изменения в админке видны гостю сразу.

## Механики, добавленные после разбора конкурентов

- **Заказ по расписанию.** На оформлении — переключатель «Как можно скорее / К определённому времени» и слоты с шагом 30 минут на сегодня и завтра. Слоты считаются от часов работы выбранной точки и от текущего времени + 60 минут на приготовление (30 минут для самовывоза). Выбранное время сохраняется в заказе, видно в оплате, в истории и в админке.
- **Адресная книга.** Два сохранённых адреса («Дом», «Офис») плюс добавление своего: выбор подставляет адрес в поле доставки, удаление убирает адрес. Книга доступна и в оформлении, и в профиле.
- **Стоп-лист.** Переключатель в админке «Меню» сразу убирает блюдо из меню гостя: карточка помечается «Нет в наличии», кнопка «+» исчезает, блюдо нельзя заказать. Возврат в меню — одной кнопкой.
- **Минимальный заказ.** Порог 300 ₽ виден в корзине («не хватает X ₽») и блокирует переход к оплате. Значение меняется в админке и сразу действует в приложении.
- **Честные аллергены.** У каждого блюда свой состав и свой список аллергенов — чизкейк содержит молоко и глютен, латте — молоко, сашими — рыбу. Раньше один и тот же текст показывался для всех блюд.
- **Экран отказа.** Отказ ресторана (с выбором причины в админке) и отмена клиентом ведут на отдельный экран: причина, что с деньгами, сумма возврата и повтор заказа в один тап. Раньше отклонённый заказ показывался гостю как «Заказ принят».
- **Избранное и повтор заказа.** Сердечко в карточке блюда и в шапке со счётчиком, отдельный экран избранного с кнопкой «Добавить всё в корзину», карточка «Повторить заказ» на главной.
- **Допродажи.** В корзине — блок «Добавьте к заказу» с блюдами, которые заказывают вместе с текущими, и кнопкой «Добавить всё».
- **Логотип → главная.** Клик по «васаби.» в шапке сбрасывает стек экранов и возвращает на главную; если гость пришёл со стола, заказ «к столу» снимается.
- **Акции на виду.** `BANNERS` в `data.js` — единственный источник акций: он питает карусель на главной, экран «Акции» и раздел «Маркетинг» в админке. Карусель листается свайпом, колёсиком и стрелками в заголовке, карточки прилипают к началу (scroll snap), следующая видна краем, точки снизу показывают позицию. Тап открывает то, что обещано в карточке: блюдо, промокод (сразу в корзине, с проверкой минимальной суммы) или экран. Предпоследняя плитка — «Все акции». В админке каждую акцию можно выключить и переставить стрелками ↑↓ — гость видит изменения сразу, потому что и лента, и экран акций читают один и тот же список. Выключенный промокод нельзя применить ни кнопкой, ни вводом вручную, а если его выключить у уже добавленного в заказ — скидка исчезает из расчёта.
- **Фильтр там, где он работает.** На главной нет чипса «Все» и вообще нет подсвеченного фильтра: там лежит лента любимого (4 блюда), а подсвеченное «Все» обещало бы 10 и выглядело сломанным. Строка «Категории» на главной — не фильтр, а быстрые переходы: обводка вместо заливки, стрелка у названия, тап открывает каталог сразу с этой категорией. В каталоге тот же ряд работает как настоящий фильтр — там и подсвеченная категория. Поиск на главной при вводе переносит в каталог с результатом и по пути сбрасывает выбранную категорию — поиск ищется по всему меню, иначе leftover-категория прятала бы половину блюд без единого следа в интерфейсе.
- **Найти своё блюдо — с первого экрана.** Поиск на главной поднят под шапку: раньше он стоял под акциями, на 1094 px от верха, и до него нужно было прокручивать полэкрана. Теперь он виден сразу, а hero-баннер целиком остаётся на первом экране.
- **Горизонтальные ленты видно, что они листаются.** У лент категорий полосы прокрутки нет, поэтому у правого края добавлено затемнение (`.chips-wrap::after`): на 360 px видно 3 категории из 7, и без этого знака гостю не сообщали, что справа есть ещё.
- **Главная: «Попробуйте любимое» ведётся из админки.** В разделе «Меню» у каждого блюда есть звезда «На главной» и отдельная панель со списком отмеченных. Метка меняет ленту на главной гостя сразу (общее состояние), лимит — 6 блюд (`RULES.featuredMax`), седьмое не добавляется: главная не должна превращаться в каталог. Блюдо из стоп-листа в ленту не попадает, и в панели это подписано. Если отметок нет — блок на главной не показывается вовсе, пустой заголовок с нулём блюд гость не видит.
- **Поля экрана.** Отступ по краям экрана — 16 px (`--pad`), он задаёт только `.section`; у `.dish-grid`, `.chips`, `.search` своих полей нет, иначе они складывались бы вдвое. Карточка блюда на экране 393 px — 175 px вместо 158 px, на 360 px — 158 px.
- **Добавление блюда — на первом экране раздела.** Форма стояла под таблицей всех блюд, то есть на третьем экране вниз: на телефоне до «Новое блюдо» надо было долистать мимо десяти позиций. Теперь форма первая в разделе «Меню», над таблицей, а в шапке таблицы есть кнопка «+ Добавить блюдо» — она возвращает к форме и ставит курсор в поле названия. Кнопка «Создать блюдо» липнет к низу окна, пока поля заполняются. Правка блюда (иконка-карандаш в строке таблицы) открывает ту же форму с уже подставленными данными.
- **Своё фото блюда — из телефона.** Раньше выбрать можно было только одну из семи картинок из набора, и владелец справедливо спросил, как загрузить снимок своего блюда. Теперь рядом с выбором из набора есть поле «Своё фото блюда»: снимок с телефона обрезается по квадрату, ужимается до 900 px и сохраняется в блюдо. Кнопка «Вернуть фото из набора» возвращает исходную картинку. Ограничение прототипа: фото живёт только в открытой вкладке — после перезагрузки страницы блюдо снова с фото из набора, потому что хранить файлы без сервера негде.
- **Метка и скидка — разные настройки.** Метка блюда («Хит», «Выбор шефа», «Новинка» или свой текст) ничего не меняет в цене. Скидка 0–90% задаётся рядом с обычной ценой: гость видит новую цену и старую зачёркнутой в каталоге, карточке, избранном и корзине. Доплаты за модификаторы не уменьшаются. Промокод применяется дополнительно к сумме корзины после скидок на блюда — это осознанное демо-правило, перед боевым запуском владельцу нужно подтвердить, что скидки должны суммироваться.
- **Свой баннер с понятными размерами.** В «Маркетинге» можно изменить уже существующую акцию, включая «−15%»: метка редактируется отдельно, а при выборе промокода подставляется автоматически. Поле «Свой баннер» принимает JPG/PNG, ужимает файл до 1600 px по ширине и показывает предпросмотр. Рекомендуемый исходник — **1600 × 800 px, горизонтальный 2:1**; важные текст и блюдо держать по центру, потому что карусель на главной обрезает верх и низ чуть сильнее, чем полный экран акции.
- **Точки и сотрудники добавляются в «Настройках».** У точки редактируются название, адрес, часы и тип работы; она сразу попадает в самовывоз, «О ресторане» и QR-листы. Сотруднику задаются имя, телефон и роль. Вход в демо-панель: «Профиль» → «Доступ сотрудника» → выбрать человека → «Открыть демо-панель»; выбранные имя и роль видны в шапке админки. Это не регистрация: SMS, пароли, приглашения и настоящее ограничение кнопок по роли требуют серверной авторизации.
- **Таблица меню читается, а не сжимается.** Колонка «Вес» была 43 px, и «32 шт. · 920 г» переносилось по одному слову в строке — строка вырастала до 121 px. Теперь у таблицы есть минимальная ширина, она прокручивается внутри своей панели (страница целиком не едет вбок), короткие колонки не переносятся, а кнопки действий стоят в одну строку: высота строки — 70 px. Широкие таблицы на телефоне (до 560 px) заменяются карточками: блюда, клиенты, промокоды, столы QR, отчёт и предпросмотр импорта.
- **Инспектор рассказывает, что уже работает.** Список «Что работает» справа от рамки разделён на «Приложение гостя» и «Админ-панель» и перечисляет то, что действительно есть в прототипе: от поиска на главной до импорта гостей из CRM. Раньше список остался от первой версии и половины уже не было в проекте. На широком экране панель листается сама: она липкая, а список стал длиннее окна — раньше её низ был просто недоступен.
- **Карточка блюда открывается всегда.** В списке экранов справа есть пункт «Карточка блюда» — раньше он открывал пустой экран («Блюдо не найдено»), потому что блюдо в нём выбрать нельзя. Теперь в этом случае показывается первое доступное блюдо, а последнее открытое — при повторном заходе. Если блюдо всё же недоступно, вместо пустоты даётся кнопка «Открыть меню».
- **Модификатор не переезжает на другое блюдо.** Идентификаторы модификаторов («острое», «авокадо», «фирменный соус») общие для всех блюд, поэтому при переходе на другое блюдо выбор сбрасывается. Раньше отмеченная доплата молча уезжала в следующую карточку и попадала в заказ.
- **Админка ведёт всё, что не приходит из iiko.** Пока касса не подключена, меню, акции и база гостей живут в панели: можно завести блюдо (оно сразу в каталоге, поиске и QR-меню), создать акцию на главной, начислить гостю баллы, удалить гостя и **залить гостей из старой CRM** — это подготовка к переезду с Foodpicasso. Перед импортом файл показывается таблицей: кого добавим, у кого обновим историю заказов, какие строки не разобрались. Сверка по телефону, а не по строке: «+7 916 330-12-04» и «8 916 330 12 04» — один и тот же гость.
- **QR-меню на столе.** Админ-панель → «QR-меню»: выбираешь точку и номера столов, получаешь ссылки вида `…index.html#menu?table=12&loc=l1`, PNG для печати и листы A4 по 4 стола. Гость сканирует код камерой, попадает на экран меню стола без регистрации, выбирает блюда и отправляет заказ «к столу» — у него свой короткий статус-флоу («Принят → Готовим → Собран → Подан к столу»), оплата у стола, время приготовления — из настроек. Стоп-лист админки действует и там. QR считается своим кодером (`qr.js`): байтовый режим, уровни L/M, версии 1–10, маски по штрафам — проверен на 34 реальных ссылках, совпадает бит в бит с библиотекой `qrcode` и читается декодером без единой синдроменной ошибки.

## Что намеренно не подключено

- **База данных и файловое хранилище.** Все правки меню, акций, точек и сотрудников, а также загруженные фото и баннеры живут только в текущей открытой вкладке. Перезагрузка возвращает демо-данные; для сохранения и совместной работы нужны сервер и база данных.
- **Авторизация и права сотрудников.** Выбор человека в «Профиле» — демонстрация интерфейса, а не вход. SMS, пароли, приглашения, сеансы и ограничение действий по роли не реализованы.
- **iiko.** Заказы не уходят в iikoDelivery, чек не печатается в iikoKitchen, бонусы iiko недоступны. Это видно прямо в интерфейсе — как в текущем приложении на Foodpicasso. Требуются лицензии iikoDelivery + iikoKitchen и API-ключи тестового стенда.
- **Оплата.** Кнопка оплаты имитирует успешный ответ; чека по 54-ФЗ нет — нужен реальный эквайринг (ЮKassa/СБП).
- **Push и SMS.** Заглушки: статус заказа меняется автоматически по таймеру, SMS-код не отправляется.
- **Геокодинг и карта.** Адрес вводится текстом, Яндекс Карты не подключены.
- **Слоты времени.** Считаются по часам работы точки в справочнике, без загрузки реального графика загрузки кухни и без подтверждения оператором.

## Экран телефона

Телефон в прототипе — нарисованная рамка на CSS (`.device`), а не эмулятор устройства и не расширение браузера: сборки нет, прототип открывается двойным кликом по `index.html`.

Размер выбирается в верхней панели — список «Размер экрана». Пресеты сняты с реальных разрешений массовых телефонов, а не округлены «под 390»: вёрстка проверяется ровно на том экране, что у гостя в руке.

| Пресет | Экран | CSS-размер | Кого представляет |
|---|---|---|---|
| iPhone 15/16 | 393 × 852 | по умолчанию | самый распространённый айфон |
| iPhone Pro Max | 430 × 932 | крупный экран | «плюс»-модели, планшетофоны |
| Pixel 8/9 | 412 × 892 | средний Android | Pixel, Xiaomi, Honor |
| Galaxy S24 | 360 × 780 | узкий Android | самый популярный Android-размер |
| iPhone SE | 375 × 667 | маленький экран | старые и бюджетные телефоны |
| Планшет | 768 × 1024 | iPad | показ гостю на планшете в зале |
| Терминал в зале | 1024 × 768 | горизонтальный | монитор кассы и киоск |
| Во весь экран | по окну | — | максимум места на мониторе |
| Свой размер… | любые числа | — | два поля «ширина × высота», применяются сразу |

Чем шире рамка, тем больше контента видно без прокрутки: сетка блюд переходит с 2 колонок на 3–4, слоты времени — с 4 на 6, инспектор переезжает под экран, а чёлка телефона исчезает.

**Рамка никогда не уменьшается ниже 90%.** Раньше она целиком вписывалась в окно и на ноутбуке сжималась до 71% — текст становился нечитаемым, кнопки мелкими для пальца. Теперь, если рамка не влезает по высоте даже в 90%, она остаётся в 90%, а нижняя часть долистывается страницей: пропорции телефона не искажаются, размер текста остаётся читабельным. О нехватке места честно сказано в инспекторе: «393 × 852 · 90% окна · низ экрана ниже, листать». Если окно уже самой рамки — она уменьшается по ширине (иначе уехала бы за экран).

**На настоящем телефоне** (ширина экрана до 560 px) муляж корпуса, статус-бар с 9:41 и масштабирование отключаются: приложение занимает весь экран ровно так, как оно выглядит у гостя, — в него можно тыкать пальцем без потерь. Инспектор и переключатель режимов остаются под ним.

Высота шапки сверху («васаби.», выбор размера, переключатель режима) измеряется в браузере и учитывается в двух местах: телефон прилипает под неё, а не за неё, и вписывается в оставшееся место. На узком окне шапка переносится в две строки — отступы пересчитываются сами.

Дополнительно:

- **Узкое окно** (до 960 px): инспектор уезжает под телефон. Там же рамка телефона перестаёт прилипать к шапке: в одной колонке прилипания она легла бы на список экранов.
- **Мобильный браузер** (до 640 px): подпись под названием в шапке скрывается, чтобы панель осталась в одну строку.

## Админ-панель на телефоне

Админка перестраивается по ширине собственного контейнера (`.admin-stage`), а не окна браузера: тот же расклад получает и телефон, и узкое окно десктопа, и колонка в половину монитора.

| Ширина панели | Что меняется |
|---|---|
| до 1100 px | блоки «два в ряд» и статистика перестроются в 2 колонки |
| до 900 px | боковое меню уходит над контентом и становится чипами в строку, отступы уменьшаются |
| до 760 px | таблицы шире панели получают свою горизонтальную прокрутку — страница целиком не уезжает |
| до 560 px | карточки заказов в одну колонку, широкие таблицы (блюда, клиенты, промокоды, столы QR, отчёт, предпросмотр импорта) заменяются карточками, вкладки статусов переносятся, кнопки вырастают до ~45 px под палец, длинный адрес меню переносится, а не режется многоточием |
| до 420 px | статистика и сетки в одну колонку, адрес `admin.vasabi.ru` в шапке окна скрывается |

Ни один раздел не прячется за прокрутку: семь пунктов меню видны все (перенос в три строки), как и все вкладки статусов. Проверено скриптом на 360, 390, 480, 640, 768, 900, 1100 и 1440 px по всем семи разделам — ни обрезанного контента, ни общей горизонтальной прокрутки.

Прокрутка вбок была: подписи для скринридера в шапках таблиц стояли по статическому месту, то есть за правым краем широкой таблицы, и на телефоне страницу можно было сдвинуть на 60–105 px. Теперь подписи прижаты к началу — проверено на всех семи разделах при ширине панели 390 и 430 px.

## Прокрутка

Перерисовка экрана не сбрасывает позицию: переключение шагатора, добавление в корзину, выбор категории и ввод в поиске сохраняют прокрутку. Кнопка «Назад» возвращает экран на ту же позицию, а переход на новый экран начинается сверху.

## Доступность и попадание пальцем

Проход по мобильным экранам с навыками `design-review` (accessibility + responsive). Мерялось скриптом в браузере: 14 экранов гостя на 360 / 375 / 393 / 430 px и все семь разделов админки.

- **Тап 44 px.** Чипсы категорий (41 px → 44 px), сегмент «Доставка / Самовывоз / К столу», кнопки «Назад», «+» в карточке, outline-кнопки и поля строк выросли до 44–48 px; в админке все кнопки и вкладки — 44 px. Мелкие иконки (сердечко избранного, стрелки карусели, удаление адреса) остались визуально 32–34 px, но получили невидимую площадку +6 px по краям — попадать надо по 44–46 px.
- **Главная кнопка не прячется.** «Оформить» и «Оплатить» прилипли к низу экрана (`.pdp-bar`, `position:sticky`): раньше на оформлении кнопка лежала на ~1400 px ниже сгиба, и её надо было искать прокруткой. Проверено на трёх позициях скролла — кнопка всегда у нижней границы.
- **Клавиатура.** Enter и Пробел срабатывают на самодельных кнопках (строки выбора адреса, способа оплаты, стола), после любой перерисовки фокус возвращается на тот же элемент, а после неудачной проверки встаёт на первое проблемное поле. Виден и лаймовый `:focus-visible`.
- **Скринридер.** У каждого экрана ровно один `h1` (в админке им стал заголовок раздела, подзаголовки панелей опустились до `h2`); самодельные контролы получили `role="button"`/`aria-pressed`, переключатели — `role="switch"`/`aria-checked`, активный пункт меню — `aria-current`, прокручиваемые таблицы админки — `role="region"` с пояснением, кнопки-иконки — имена, колонки таблиц — `scope="col"`, `role="application"` убран.
- **Страница не уезжает вбок.** Подписи, которые читает только скринридер (`.sr-only`), стояли по статическому месту — то есть в самом правом краю широкой таблицы админки, и растягивали страницу на 60–105 px: на телефоне её можно было случайно сдвинуть вбок. Теперь они прижаты к началу (`left:0`) и больше не тянут за собой страницу.
- **Ошибки полей.** `aria-invalid` + `aria-describedby` на само поле и `role="alert"` на текст ошибки: «Укажите адрес» теперь озвучивается и привязан к полю, а не просто нарисован красным.
- **Мобильный ввод.** У полей появились `autocomplete` (имя, телефон, адрес, `one-time-code` для кода SMS), `inputmode` для цифр, `enterkeyhint` («Далее» / «Готово» вместо «Enter» в середине формы) и `autocapitalize` — телефон не набирается в нижнем регистре, промокод сам становится ЗАГЛАВНЫМИ.
- **Мельчайший текст.** Нижняя граница — 11,5 px; остались 11 px только счётчики внутри пилюль 17–18 px (больше в них не влезает). Контраст проверен с учётом наложения полупрозрачных фонов — падений нет.

Аудит ручной (без axe-сканера): текст поверх фото и реальную озвучку скринридером скриптом не проверить — это смотрит человек.

## Публикация (GitHub Pages)

Прототип — обычные статичные файлы, сервер не нужен. `index.html` в корне репозитория, Pages раздаёт его по адресу `https://<логин>.github.io/<репозиторий>/` с HTTPS и без оплаты.

1. Завести репозиторий (имя, например `food-proto`) и включить в нём Pages: Settings → Pages → Source: Deploy from a branch → `main` / root.
2. Открыть ссылку с телефона — QR-коды из админки начнут вести на этот же адрес автоматически (`menuUrl()` берёт текущий домен), перегенерировать листы не нужно.
3. Ссылку можно укоротить редиректом, если для печати она слишком длинная.

Из России GitHub Pages открывается нестабильно: для показа гостям и печатных листов надёжнее любой российский статический хостинг с тем же `index.html` — код от этого не меняется.
